## الهدف

توطين كل ما يلزم لعرض صفحات مصحف المدينة الـ604 (رواية حفص) محلياً بدقة الطباعة، بصيغة جاهزة للاستهلاك: بيانات تخطيط (صفحة→أسطر→كلمات) + خطوط QPC + نص كل كلمة، مع **تحقق قرآني صارم** — هذا نص القرآن ولا يُقبل فيه احتمال خطأ.

## المصادر (مرتبة بالأفضلية — تحقق وجرب بالترتيب)

1. **QUL (qul.tarteel.ai)** — Quranic Universal Library من Tarteel:
   - تخطيطات المصحف: https://qul.tarteel.ai/resources/mushaf-layout — اختر تخطيط **QPC V2** (604 صفحات، 15 سطراً) وحمّل SQLite أو JSON.
   - الخطوط: https://qul.tarteel.ai/resources/font — خطوط QPC V2 صفحة-بصفحة (ملف خط لكل صفحة) أو الخط الموحد.
   - نص الكلمات: مورد word-by-word script (نص عثماني لكل كلمة بمعرفها).
2. **مرآة GitHub للخطوط**: https://github.com/nuqayah/qpc-fonts — ملفات الخطوط الخام بروابط مستقرة قابلة للأتمتة (تحقق أنها QPC V2 وبأي صيغة woff2/ttf).
3. fallback للتخطيط إن تعذر QUL: بيانات pages/lines من واجهة quran.com API v4 (`/verses/by_page/{n}?words=true` تعطي لكل كلمة line_number وcode_v2) — لكن وثّق أي مصدر استخدمته بدقة.

ملاحظة تراخيص: كل هذه المصادر مجانية الاستخدام مع الإسناد؛ أنشئ `docs/CREDITS.md` يسند إلى: مجمع الملك فهد (الخطوط)، QUL/Tarteel (البيانات)، Tanzil (النص) — بصياغة موجزة لائقة (استثناء وحيد من منع docs: هذا الملف الجديد فقط).

## المخرجات

### 1. سكربت الجلب `scripts/fetch-mushaf-assets.mjs` (يعمل داخل حاوية node)
- يحمّل خطوط الصفحات الـ604 (woff2 المفضل) إلى `frontend/public/fonts/qpc-v2/p{NNN}.woff2` — **المجلد يُضاف إلى .gitignore** (عشرات الميغابايتات لا تُلتزم؛ السكربت هو المرجع). idempotent: يتخطى الموجود، يعيد المحاولة عند الفشل، ويطبع ملخصاً.
- شغّله فعلياً حتى اكتمال الـ604 وتحقق من أحجام الملفات (لا ملفات فارغة/صفحات HTML خطأ — افحص magic bytes لـ woff2).

### 2. بيانات التخطيط `backend/app/data/mushaf_qpc_v2.json` (يُلتزم في git)
بنية لكل صفحة (1..604): أسطر الصفحة بترتيبها، نوع السطر (بسملة/اسم سورة/آيات)، ولكل كلمة: `{surah, ayah, word (ترتيبها في الآية), text_uthmani, glyph (نص الحرف/الكود لخط QPC V2), is_ayah_marker}`. أضف فهرساً مساعداً: لكل (سورة، آية) → رقم الصفحة والسطر الأول. اضغط الحجم بمفاتيح قصيرة إن لزم (الملف قد يبلغ عدة ميغابايتات — مقبول).

### 3. واجهات خلفية (`backend/app/api/routes/mushaf.py`)
- `GET /api/mushaf/pages/{n}` — تخطيط الصفحة (1..604، تحقق حدود برسالة عربية). متاح لكل الأدوار المسجلة **بمن فيهم الطالب**.
- `GET /api/mushaf/page-for?surah=&ayah=` — رقم الصفحة (تحقق بحدود quran_meta).
- تحميل الـ JSON مرة واحدة عند الإقلاع (lazy singleton)، لا قراءة ملف لكل طلب.

### 4. التحقق القرآني الصارم (اختبارات pytest — هذا قلب الحزمة)
- عدد الصفحات = 604 بالضبط.
- كل آيات المصحف (6236 وفق `SURAH_AYAH_COUNTS` القائمة) تظهر كلماتها، وكل (سورة، آية) تقع في صفحة واحدة معروفة، ولا آية مفقودة ولا مكررة عبر الصفحات.
- الصفحة 1 = الفاتحة كاملة (7 آيات)؛ الصفحة 2 تبدأ بأول البقرة؛ الصفحة 604 تنتهي بآخر الناس.
- ترتيب الكلمات داخل كل آية متسلسل بلا فجوات، وترتيب الآيات مصحفي.
- عدد أسطر الصفحات القياسية = 15 (مع استثناءات الصفحتين 1 و2 الموثقة).
- مطابقة عينات نصية: نص `text_uthmani` لعشر آيات موزعة (منها 1:1، 2:255، 18:1، 112:1-4، 114:6) يطابق حرفياً نص Tanzil العثماني (ضمّن النص المتوقع في الاختبار نفسه بعد تحقق يدوي منه أثناء عملك).
- كل صفحة لها ملف خط موجود فعلاً على القرص (اختبار يعمل فقط عند وجود المجلد — skip بوضوح إن لم تُجلب الخطوط في بيئة الاختبار).
- **إن فشل أي تحقق: لا تسلّم — أصلح البيانات أو المصدر.** عدم اليقين في نص القرآن = فشل الحزمة كلها.

### 5. صفحة تحقق بصري مؤقتة
Route تطويري `/dev/mushaf/{n}` (DEV فقط مثل `/dev/ui`): يعرض الصفحة بخطها (`@font-face` ديناميكي لخط الصفحة) سطراً-بسطر خام (بلا تصميم نهائي — ذلك WP9b). التقط لقطات للصفحات 1، 2، 50، 255 (البقرة 255)، 604 وافحصها بعينك مقابل صور مصحف المدينة المطبوع (ابحث عن صور مرجعية للمقارنة)، وضعها في scratchpad `wp9a/`.
