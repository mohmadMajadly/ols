# خطة مشروع OLS — منصة إدارة التسميع لمحفظي القرآن الكريم

> وثيقة العمل المرجعية. آخر تحديث: 2026-08-29. كل وكيل تنفيذي يقرأ هذه الوثيقة قبل البدء.

## 1. الرؤية

منصة محلية (Local-first) لمحفظي القرآن ومدققي التجويد تدير الطلاب وجلسات التسميع، بحيث تُسجَّل تلاوة الطالب صوتياً وتُدوَّن الملاحظات مربوطة باللحظة الزمنية الدقيقة، مع ملف احترافي لكل طالب ولوحة إحصائيات عامة.

**الميزة التنافسية المؤكدة بالبحث:** لا توجد منصة في السوق (معارج، حلقتي، Halaqaty، MarkTrack، QuranRecord…) تقدم تصنيفاً بنيوياً للأخطاء مربوطاً بالتسجيل الصوتي؛ كلها تكتفي بدرجة إجمالية أو ملاحظة حرة. تحليلات الأخطاء حسب التصنيف عبر الزمن (heatmaps، اتجاهات) فجوة حقيقية في السوق.

## 2. درجات النجاح (أولويات المستخدم)

1. **MVP — إلزامي 100%**: تسجيل صوتي للجلسة، ملاحظات موقوتة، ملف طالب، Dashboard عام قابل للفلترة، تخصيص ديناميكي لتصنيفات الملاحظات.
2. حسابات دخول للطلاب (اطلاع على إحصائياتهم وتسجيلاتهم).
3. عرض صفحة المصحف مع تتبع آني للكلمة المقروءة (Highlighting).
4. كشف تلقائي لأخطاء الحفظ (آية منسية، زيادة/نقص).
5. الدرجة القصوى: كشف أحكام التجويد تلقائياً (بحثي — بدون وعود).

## 3. خلاصة البحث التقني (مثبتة بالمصادر)

### بيانات القرآن — كلها متاحة مجاناً ومحلياً
- **النص**: Tanzil.net نص عثماني مدقق (لا يجوز تعديل النص، مع الإسناد). QUL (qul.tarteel.ai) يوفر SQLite/JSON جاهزة: نص كلمة-بكلمة، ميتاداتا (جزء/حزب/صفحة).
- **تخطيط صفحات المصحف**: QUL Mushaf Layouts — جداول page/line/word لمحاكاة مصحف المدينة الـ604 صفحة بدقة الطباعة، مع خطوط مجمع الملك فهد QPC V1/V2 (glyph-based). الترخيص يسمح بالتضمين.
- **التجويد الملوّن**: cpfair/quran-tajweed (JSON بمواقع الأحكام حرفياً) أو نص QUL Uthmani-Tajweed.
- **الصوت المرجعي**: تلاوات QUL المقسّمة بطوابع زمنية لكل كلمة `[word, start_ms, end_ms]` (نفس بيانات quran.com).

### التعرف الصوتي (الدرجات 3–5)
- **الدرجة 3 (تتبع)**: ممكنة محلياً — `tarteel-ai/whisper-base-ar-quran` (WER ~5.75) عبر faster-whisper INT8 على CPU، بث مقطعي بكمون 0.5–2 ثانية، مطابقة fuzzy/Needleman-Wunsch مع النص المعروف مسبقاً. مرجع مفتوح المصدر: `yayaiu6/Real-Time-Quran-recitation-tracker-System`.
- **الدرجة 4 (كشف أخطاء الحفظ)**: امتداد للتتبع — diff بين الكلمات المتعرَّف عليها والنص المتوقع. دقة "مساعد للمعلم" لا "حكم قطعي" (خطأ النموذج ~6%) — القرار النهائي دائماً للمعلم.
- **الدرجة 5 (تجويد)**: research-grade فقط عالمياً؛ الأبحاث تغطي 3–4 أحكام (مد، غنة، إخفاء، قلقلة) بنماذج ضيقة على QDAT dataset. تُعامل كمرحلة بحثية تجريبية (Beta) لاحقة.
- **لا يوجد API تجاري بديل**: Tarteel لا تقدم API عاماً. الخيار التجاري الوحيد الجاد للعربية عموماً هو Munsit (غير مخصص للقرآن). الحل المحلي هو الأفضل فعلياً وليس مجرد تفضيل.

## 4. تصنيف الملاحظات الافتراضي (Seed — قابل للتعديل ديناميكياً)

مبني على التصنيف الشرعي المعياري (لحن جلي/خفي) ولوائح تحكيم المسابقات (السلطان قابوس، دبي الدولية):

### أ. أخطاء الحفظ (اللحن الجلي)
| النوع | أمثلة فرعية |
|---|---|
| إبدال | حرف / حركة / كلمة |
| زيادة | حرف / حركة / كلمة |
| نقص | حرف / حركة / كلمة |
| تقديم وتأخير | كلمات أو آيات |
| تردد / تلعثم | — |
| نسيان آية | — |
| خلط متشابهات | انتقال لآية مشابهة في موضع آخر |

### ب. أخطاء التجويد (اللحن الخفي)
المدود (بأنواعها)، الغنة، المخارج والصفات، التفخيم والترقيق، القلقلة، الإدغام/الإخفاء/الإقلاب/الإظهار.

### ج. الضبط والتشكيل
تحريك ساكن / تسكين متحرك / خطأ حركة إعرابية.

### د. الوقف والابتداء
وقف قبيح، ابتداء غير صحيح، ترك وقف لازم.

### خصائص كل ملاحظة
- **الطابع الزمني**: يُلتقط لحظة الضغط على زر الملاحظة (وليس لحظة إتمام الكتابة).
- **طريقة التصحيح** (من لوائح التحكيم): تدارك ذاتي (بلا خصم) / تنبيه (خصم صغير) / تلقين "فُتح عليه" (خصم أكبر).
- **الشدة**: خفيف / متوسط / جسيم.
- **الموضع**: سورة:آية (اختياري، إدخال سريع).
- نص حر + وسوم.
- **قاعدة مرونة**: التصنيفات والحقول قابلة للإضافة/التعديل/الإخفاء من الإعدادات (بأسلوب جداول مرن أنيق) — التصنيف أعلاه مجرد بذرة افتراضية.

## 5. بنية البيانات (Data Model — ملخص)

- **Teacher/User**: (مستقبلاً أدوار: معلم/مشرف/طالب).
- **Group (حلقة)**: اسم، وصف، طلاب.
- **Student**: بيانات شخصية، حلقة، تاريخ التحاق، خطة الحفظ، حساب دخول (درجة 2).
- **Session (جلسة تسميع)**: طالب، تاريخ، نوع (سبق جديد / مراجعة صغرى "سبقيات" / مراجعة كبرى)، النطاق (من سورة:آية إلى سورة:آية أو صفحات)، تسجيل صوتي، درجة (مقترحة تلقائياً من الخصومات، قابلة للتعديل)، حالة حضور.
- **Recording**: ملف صوتي على القرص (رفع مقطعي أثناء التسجيل لحمايته من الانقطاع)، مدة، waveform data.
- **Note**: session، timestamp_ms، تصنيف، نوع فرعي، شدة، طريقة تصحيح، سورة:آية، نص حر.
- **NoteCategory / NoteField**: التصنيفات والحقول الديناميكية (schema مرن).
- **Rubric**: أوزان الدرجات وقيم الخصومات — قابلة للتخصيص (افتراضي مستلهم من المسابقات: حفظ 70%، تجويد 25%، أداء 5%).
- **QuranRef**: قاعدة مرجعية مدمجة (سور/آيات/صفحات/أجزاء) من QUL لاختيار النطاقات وربط الملاحظات.

## 6. الميزات المقترحة للمعلم (إضافة لما طلبه المستخدم)

**ضمن الـ MVP (رخيصة التنفيذ، عالية القيمة):**
1. مشغّل صوتي بمخطط موجي (waveform) عليه علامات الملاحظات — نقرة على الملاحظة تقفز للتسجيل قبلها بـ5 ثوانٍ.
2. أزرار ملاحظات سريعة (تصنيف بنقرة واحدة) أثناء الجلسة + إمكانية التفصيل لاحقاً.
3. اقتراح درجة تلقائي من الخصومات وفق الـ Rubric، مع حرية التعديل اليدوي.
4. خريطة حفظ تراكمية للطالب (جزء-بجزء / سورة-بسورة، ملونة بمستوى الإتقان).
5. كشف الخطأ المتكرر: تنبيه عندما يتكرر خطأ في نفس الموضع/النوع عبر الجلسات.
6. تسجيل الحضور والغياب بنقرة (table stakes في كل المنصات المنافسة).
7. أنواع الجلسات وفق المنهجية المعتمدة: سبق / سبقيات / مراجعة كبرى.

**مراحل لاحقة (بعد MVP):**
8. تقرير ولي الأمر: PDF أنيق أو نص جاهز للواتساب.
9. توقع تاريخ الختم من وتيرة الطالب الفعلية.
10. Heatmap مواطن الضعف على صفحات المصحف (أين تتركز الأخطاء).
11. تصدير/استيراد نسخة احتياطية كاملة (ملف واحد).
11ب. تنقل أسرع في لوحة مصحف الجلسة: إدخال رقم صفحة + قفز لسورة (طلب المستخدم 2026-08-29 — مؤجل للمرحلة القادمة؛ موجود أصلاً في صفحة /mushaf المستقلة).
12. أرشيف شهادات وإنجازات.

## 7. المعمارية التقنية (محدّثة بقرارات 2026-08-29)

- **الشكل**: تطبيق ويب يُنشر على سيرفر عام على الإنترنت (Docker Compose) ويُستخدم من أي مكان. التطوير محلياً على جهاز المستخدم بنفس الـ compose.
- **النطاق**: مركز واحد متعدد المستخدمين بأدوار: **مدير (Admin) / مشرف / معلم / طالب** — من اليوم الأول، حتى لو استُخدم بمعلم واحد حالياً.
- **Frontend**: React + Vite + TypeScript + Tailwind v4 بثيم مخصص بالكامل (لا defaults)، RTL عربي، تصميم وفق سكيل frontend-design — احترافية قصوى، لا مظهر قوالب AI.
- **Backend**: Python FastAPI (يوحّد المنصة مع خدمات ASR المستقبلية) + **PostgreSQL** (نشر عام متعدد المستخدمين) + ملفات الصوت على القرص خلف مصادقة (لا روابط عامة).
- **الأمان (إلزامي للنشر العام)**: تجزئة كلمات المرور Argon2، JWT في httpOnly cookies، RBAC صارم (الطالب يرى نفسه فقط)، Rate limiting على الدخول، HTTPS عبر Caddy (شهادات تلقائية)، حساب الأدمن يُزرع من متغيرات بيئة عند أول تشغيل.
- **التسجيل**: MediaRecorder برفع مقطعي (chunks كل ~5 ثوانٍ) — انقطاع الاتصال أو تعليق المتصفح لا يُضيع الجلسة؛ استئناف تلقائي. (MediaRecorder يتطلب HTTPS خارج localhost.)
- **درجة 3+**: خدمة ASR منفصلة في Docker (faster-whisper + محاذاة)، تتخاطب مع الواجهة عبر WebSocket.
- **الخطوط**: QPC V1/V2 مدمجة محلياً + بيانات تخطيط الصفحات من QUL SQLite. الرواية: **حفص عن عاصم** فقط في البداية.

## 8. مراحل التنفيذ

### المرحلة 0 — الأساس (Infrastructure)
هيكل المشروع، Docker Compose، قاعدة البيانات والـ migrations، تحميل بيانات QuranRef من QUL، نظام التصميم (design tokens، الخطوط العربية، مكتبة مكونات أساسية).
**بوابة القبول**: التطبيق يقلع بأمر واحد، صفحة فارغة بهوية بصرية مكتملة.

### المرحلة 1 — MVP (الدرجة الأولى، إلزامي)
1. **WP1**: إدارة الطلاب والحلقات (CRUD + بحث + استيراد سريع).
2. **WP2**: جلسة التسميع — التسجيل الفوري، أزرار الملاحظات الموقوتة، اختيار النطاق، الحضور، إنهاء الجلسة بدرجة مقترحة.
3. **WP3**: ملف الطالب — سجل الجلسات، مشغّل الصوت بعلامات الملاحظات، خريطة الحفظ، إحصائيات الأخطاء.
4. **WP4**: Dashboard عام — فلاتر (حلقة/فترة/نوع جلسة/تصنيف خطأ)، رسوم بيانية وفق سكيل dataviz.
5. **WP5**: الإعدادات — محرر التصنيفات والحقول الديناميكي (شكل جداول مرن أنيق) + محرر الـ Rubric.
**بوابة القبول**: سيناريو كامل حقيقي: إضافة طالب → جلسة مسجلة بملاحظات موقوتة → مراجعتها في ملف الطالب → ظهورها في الـ Dashboard. مراجعة جودة + مراجعة تصميم بصرية من المدير (أنا).

### المرحلة 2 — حسابات الطلاب
مصادقة (أدوار)، بوابة الطالب: إحصائياته، أخطاؤه، تسجيلاته الصوتية. صلاحيات صارمة (الطالب يرى نفسه فقط).

### المرحلة 3 — المصحف والتتبع الآني
1. عرض صفحة المصحف بدقة الطباعة (QPC fonts + QUL layout) مع تلوين تجويد اختياري.
2. خدمة ASR بثّية (faster-whisper INT8 + مطابقة النص المعروف) وتظليل الكلمة/الآية الجارية.
**بوابة القبول**: تتبع مستقر بكمون ≤ 2 ثانية على CPU لتلاوة مرتلة واضحة.

### المرحلة 4 — كشف أخطاء الحفظ
Diff آني ضد النص المتوقع: آية منسية بالأحمر، زيادة/نقص. يُعرض **كاقتراح** للمعلم (يقبله فيتحول لملاحظة موقوتة تلقائياً) — لا حكم آلي نهائي.

### المرحلة 5 — التجويد (بحثية، Beta)
تجارب على أحكام محدودة (مد، غنة، قلقلة) وفق أبحاث QDAT. لا تُطلق إلا بدقة مقبولة وبوسم "تجريبي".

## 9. قواعد التنفيذ الإدارية

- المدير (Fable): تخطيط، مراجعة كود وتصميم، وينفذ شخصياً الأجزاء المعقدة فعلاً.
- التنفيذ: وكلاء Sonnet حصراً. **لكل Work Package ملف مواصفات مخصص** في `docs/specs/WP*.md` يُكتب بيد المدير ويُسلَّم للوكيل في برومبته — لا يُترك الوكيل يستنتج من الخطة العامة. المدير مسؤول عن نتيجة عمل وكلائه.
- أي عمل UI: الوكيل يلتزم بتوجيهات التصميم المكتوبة له + سكيل frontend-design.
- كل WP يمر ببوابة مراجعة (كود + تشغيل فعلي + مظهر) قبل القبول. لا عمل نصفي — المحتوى قرآني والدقة أولوية مطلقة.

## 10. القرارات المعتمدة (2026-08-29)

1. **النشر**: سيرفر عام على الإنترنت — الأمان والمصادقة من اليوم الأول، وحساب الأدمن username/password يُهيأ عند أول تشغيل.
2. **النطاق**: بنية مركز كامل (مدير/مشرفون/معلمون/طلاب) من البداية، حتى لو بدأ الاستخدام بمعلم واحد.
3. **الرواية**: حفص عن عاصم فقط في البداية.
4. **بيئة التطوير**: لا Node/Python على جهاز المستخدم — كل التطوير والتشغيل عبر Docker (متوفر: Docker 29.7.2 + Git).
